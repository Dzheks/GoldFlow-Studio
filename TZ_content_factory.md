# ТЗ: Контент-завод (сценарий → готовые кадры с таймингом)

## Идея одной строкой
Кидаешь сценарий (или описание — тогда сценарий пишется сам), выбираешь стиль,
жмёшь «Пуск» — инструмент сам режет сценарий на кадры, для каждого генерит
промпт, расставляет по таймкодам под озвучку и генерит картинки. На выходе —
папка с промптами/картинками/таймингом, готовая для уже существующего
Remotion-рендерера этого проекта (pipeline/build_accent_captions_composition.py
и соседние скрипты).

Референсы, на которые ориентируемся: GoldFlow «Контент-завод» (studio/factory),
MoneyPrinterTurbo (открытый локальный аналог), видео-обзор TryAIToday Flow
Automator (см. транскрипт в этой же сессии — синтаксис `#имя`/`@имя` для
именования и переиспользования референсов).

## Форма поставки (два этапа, не одновременно)
1. **Этап 1 — Python CLI-скрипт.** Без интерфейса, запускается из терминала:
   `python content_factory.py --script vo_script.md --style disaster-specialist --out project/`
   Цель: проверить, что сама логика (резка на кадры, промпты, тайминг) работает
   правильно, прежде чем тратить время на UI.
2. **Этап 2 — локальный веб-интерфейс** (как MoneyPrinterTurbo): маленький
   сервер на компе (FastAPI/Flask) + открываешь браузер на `localhost` —
   кнопка «Пуск», загрузка сценария файлом, выбор стиля из галереи, прогресс
   по кадрам. Начинать только после того, как Этап 1 подтверждён живыми
   тестами на 2-3 реальных сценариях.

## Вход
- **Сценарий**: либо готовый текстовый файл (.md/.txt), либо короткое
  описание темы + канал/формат → тогда сценарий сначала пишется LLM
  (см. «Придумать по описанию» в GoldFlow — тема, язык, целевая длина в
  минутах, жанр/тон).
- **Стиль**: выбор из уже описанных в проекте стилей канала (например,
  disaster-specialist для BCF — hand-drawn/cel-shaded 2D editorial cartoon,
  см. reference_bcf_prompt_structure.md в памяти) — стиль фиксирует
  единый визуальный промпт-суффикс для всех кадров.
- **Озвучка**: см. открытый вопрос ниже — либо готовый MP3 (текущая практика
  проекта — VO_before_prompts: всегда сначала реальная озвучка, число кадров
  считать по факту аудио, не по прикидке слов), либо TTS внутри конвейера.

## Этапы конвейера
1. **Раскадровка (storyboard split).** LLM режет сценарий на пронумерованные
   кадры по смысловым единицам (предложение/абзац), оценивает «хватает ли
   текста для насыщенного кадра» (если абзац короткий — объединяет с соседним
   или помечает «нужен доп. текст», как у GoldFlow — «не хватает: 25 слов из
   абзаца»). Плотность — ориентир ~4.5с/кадр
   (см. reference_frame_density_pipeline.md).
2. **Разбор персонажей и локаций.** Отдельный LLM-проход по всему сценарию:
   вытащить список действующих лиц и локаций (имя/роль/краткое описание
   внешности), под каждого — слот для референса (своё фото или сгенерить).
   Для BCF-каналов сейчас правило «один референс персонажа на всё видео»
   (feedback_single_character_ref.md) — учитывать при проектировании: не
   плодить референсы «по уровням», один устойчивый персонаж.
3. **Генерация промптов по кадрам.** Для каждого кадра — построчный промпт в
   формате `[С РЕФОМ]/[БЕЗ РЕФА]/[ДИАГРАММА]` + ACTION/CAMERA (эталон:
   reference_bcf_prompt_structure.md, whisk_all_ordered.txt), с меткой
   `#имя` для называния результата и `@имя` для ссылки на уже
   сгенерированный в этой же партии кадр-референс (персонажа/сцену) —
   синтаксис подтверждён рабочим видео-обзором конкурентного инструмента.
   Теги без ведущих нулей (F1, не F001) — feedback_tag_format_no_zeros.md.
4. **Тайминг под озвучку.** Если MP3 уже есть — Whisper word-level тайминг,
   матчинг кадров по строкам скрипта против слов (не жадная нарезка по
   3-5с — см. feedback_scene_timing_pipeline.md), длинные реплики делить на
   main+extras. Если озвучки нет — сначала TTS, потом тот же матчинг.
5. **Генерация изображений.** Пакетно, с учётом уже собранных референсов
   персонажей/сцен по `@имя`. Технически — то же самое направление, что
   разобрано для bulkgen-studio в этой сессии: прямой batchexecute-запрос
   к Flow (rpcid `ogiZ0b` генерация, `maseQ` загрузка референса,
   recaptcha через `grecaptcha.enterprise.execute` без клика, XSRF из
   `window.WIZ_global_data`) — либо, если решим не завязываться на Flow,
   любой другой image-API по выбору.
6. **Выходные файлы.** Структура, совместимая с текущим Remotion-пайплайном
   проекта: `frames/` (картинки, имена по тегам), `render_sequence.csv`
   (order, shot_id, filename, start_sec, end_sec, duration_sec),
   `subtitles.srt`, `alignment.csv` (если был Whisper-тайминг) — то есть
   на выходе Этапа 1 можно сразу скормить существующим
   build_accent_captions_composition.py / build_captioned_composition.py
   без переделки рендерера.

## Решённые вопросы
1. **Источник озвучки — РЕШЕНО: Lumean API.** TTS генерится внутри
   конвейера через Lumean (голос BCF = Tazo, см. reference_voicer_api.md).
   Порядок: сценарий → Lumean TTS → реальный MP3 → Whisper word-тайминг →
   матчинг кадров. Lumean также отдаёт character-level alignment (как в
   rebuild_timing_from_alignment.py), можно использовать его вместо/вместе
   с Whisper для точного тайминга.

2. **Источник картинок — РЕШЕНО: Flow (прямой batchexecute).** Тот же
   транспорт, что разобран в bulkgen-studio в этой сессии:
   - генерация: rpcid `ogiZ0b`, тело buildGenerateImageArgs, модель по
     умолчанию NARWHAL (Nano Banana Pro) / GEM_PIX_2 / HARBOR_SEAL;
   - загрузка референса: rpcid `maseQ` → mediaId, передаётся как imageInputs;
   - авторизация: `grecaptcha.enterprise.execute(siteKey,{action:"IMAGE_GENERATION"})`
     напрямую (без клика) + XSRF/сессия из `window.WIZ_global_data`
     (SNlM0e/cfb2h/FdrFJe);
   - site key: 6LdsFiUsAAAAAIjVDZcuLhaHiDn5nnHVXVRQGeMV;
   - результат приходит синхронно в ответе (URL flow-content.google/image/...).
   ВАЖНО: это работает только внутри вкладки flow.google.com (нужны cookies
   + WIZ_global_data страницы). Значит генерация кадров идёт через
   расширение/скрипт, инжектящийся в открытую вкладку Flow — не «чистый»
   серверный API. Учесть при архитектуре: конвейер на Этапе 1 либо
   переиспользует bulkgen-studio как исполнителя генерации, либо инжектит
   тот же код в вкладку Flow.

## Решённые вопросы (продолжение)
3. **LLM для раскадровки/промптов — РЕШЕНО (2026-09-24): Gemini API,
   тот же ключ, что и для картинок.** Реализовано в goldflow-studio
   (`server.ts` → `/api/generate-script`, модель `gemini-2.5-pro`,
   structured JSON через `responseSchema`) — один `GEMINI_API_KEY` закрывает
   и текст (сценарий/раскадровку), и картинки (Nano Banana через
   `/api/generate-image`), и видео (Veo3, уже было). Также пересмотрено
   решение про картинки: **основной движок — официальный Gemini API
   (Nano Banana/Nano Banana Pro), не прямой batchexecute к Flow** — тот же
   SDK, без recaptcha/same-origin моста. Мост к Flow (batchexecute) остаётся
   в плане как ВТОРОЙ движок для экономии на объёме (см. CLAUDE.md проекта).

## Что НЕ входит в MVP (Этап 1)
- Визуальный редактор/таймлайн (это Этап 2 и позже).
- Монтаж/сборка в .mp4 внутри самого инструмента — рендер остаётся на
  существующем Remotion-пайплайне проекта, конвейер только готовит вход
  для него.
- Регистрация, оплата, лимиты — инструмент для личного использования,
  не SaaS.
