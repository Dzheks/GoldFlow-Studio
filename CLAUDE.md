# GoldFlow Studio — статус проекта (обновлено 2026-09-25)

Собрано через AI-билдер (Gemini/Google AI Studio Build) по образцу реального
сайта goldflow.ru. Реальный Node/Express-бэкенд (`server.ts`, `npm run dev`
через `tsx`). Репозиторий: https://github.com/Dzheks/GoldFlow-Studio

## Ключи в `.env` — оба реальные и рабочие
Сами значения ключей лежат только в `.env` (он в `.gitignore`, в репозиторий
не попадает) — сюда их не вписывать даже временно (один раз уже случайно
попали в этот файл текстом и заблокировали push GitHub'ом — см. ниже).
Проверка: `curl localhost:3000/api/health` → `hasApiKey:true, hasLumeanKey:true`.
⚠️ **Рекомендовано перевыпустить оба ключа** (Gemini, Lumean) — раньше лежали
открытым текстом в этом файле почти всю сессию до пуша на GitHub.
⚠️ `gemini-2.5-pro` **отключена для новых ключей** — текст идёт через
`gemini-3.1-pro-preview`.

## Что реально работает
Основной экран — `ContentFactory.tsx`, вкладка «Пакетная мастерская» (дефолт).

- **01-03 Сценарий** — `/api/generate-script` (Gemini, structured JSON).
  Два режима:
  - **«Придумать по описанию»** — ИИ пишет сюжет с нуля под тему +
    хронометраж. `targetBlockCount = clamp(round(targetSeconds/4), 3, 25)`.
    **Потолок 25 блоков за один вызов** — больше не укладывается в разумное
    время. Для роликов на 20-30 мин с нуля по теме это НЕ решено —
    архитектурный вопрос, юзер не давал добро на чанкинг, **не начинать
    без явного «да»**.
  - **«У меня свой текст»** (`mode:'custom'`) — дословный вставленный текст,
    ни слова не меняется. Реальный конвейер:
    1. `splitScriptIntoParagraphGroups()` / `splitScriptIntoSentenceLines()`
       (`src/utils/autoAssembly.ts`) — режет на предложения по ./!/?, абзацы
       остаются целыми (никогда не разрезаются посреди батча).
    2. `groupParagraphsIntoBatches()` — упаковывает целые абзацы в батчи по
       ~20 строк (нельзя резать абзац посередине — ИИ должен видеть
       законченную мысль).
    3. Каждый батч уходит на сервер (`mode:'custom'`) — ИИ **сам** решает,
       сколько кадров нужно по смыслу (смена места/времени/лица = новый
       кадр), переводит построчно если язык не совпадает, честно
       реконструирует текст из индексов (не доверяет тому, что ИИ
       "написал"). Имя героя прокидывается между батчами (`heroOverride`),
       чтобы не менялся посреди истории. При падении батча — сохраняет уже
       готовое, не теряет оплаченные кредиты.
    4. **`splitScenesByDurationCap()`** (`autoAssembly.ts`) — отдельный
       проход ПОСЛЕ того как ИИ решил смысловые границы: если итоговая
       сцена звучит дольше 4 сек, режет на N ровных кадров-ракурсов одной
       и той же сцены (`N = floor(сек/4)`, каждая часть не короче 4 сек —
       9с→2×4.5с, 12с→3×4с, 6с не режется). Каждый под-кадр получает тот
       же текст, но с добавленным указанием на другой ракурс (wide/medium/
       close-up/low-angle и т.д.). **Логика проверена изолированно и
       верна**, но в последнем живом тесте юзер видел 78→78 без изменений
       — подозрение на устаревший Vite HMR-бандл в его вкладке (просил
       сделать Ctrl+Shift+R), **подтверждения что заработало НЕТ**, это
       первое, что проверить в начале следующей сессии.
  - `nineFields`/`heroMaster.appearance/clothing/keyFeature` всегда на
    английском (промпты для картинок), остальное — на выбранном языке.

- **04 Эталон героя** — после сценария автоматически генерится портрет
  (Nano Banana), сохраняется в `heroRefImage`, передаётся как
  `heroReferenceImage` в каждый кадр батча. Реально учитывает выбранный
  кастомный стиль (раньше игнорировал — исправлено).

- **Персонажи и локации** — реальная секция (юзер сначала попросил убрать,
  подумав что у конкурента её нет, но передумал — она нужна для
  «Эталон героя» логики). «+ добавить» реально открывает модалку с
  загрузкой референс-фото персонажа/локации (`CharacterReferenceModal.tsx`).
  «Разобрать сценарий» мержит по имени, не затирает вручную добавленные
  фото при повторном запуске. Референсы с фото подставляются в генерацию
  по упоминанию имени в тексте кадра (`castReferences` в `/api/generate-image`).

- **Стиль** — «Без стиля» + кастомные стили. `CreateStyleModal.tsx` — до 6
  эталонных фото + негативный промпт, теперь **с реальным редактированием и
  удалением** (раньше только создание). Все картинки хранятся как data URL
  (не blob: URL — тот не переживает перезагрузку страницы).

- **05 Оживление (Ken Burns)** — не моя правка, проверено вживую, работает.

- **06 Монтаж по словам озвучки** — реально работает через Lumean TTS
  (`/api/synthesize-voice`), см. рецепт ниже. ⚠️ НЕ проверено: подхватывает
  ли плеер/рендер Монтажа `narrationAudioUrl` для реального аудио.

- **Материалы** (список сгенерированных кадров) — вертикальные карточки
  (кадр → номер → описание → «Перегенерировать»), не голая сетка миниатюр.
  Перегенерация реально зовёт Gemini (раньше рисовала canvas-заглушку).
  Кнопка «Скачать архивом» — реальный ZIP всех кадров (`jszip`).

- **Видео** (`VideoStudio.tsx`) — полностью переписан под референс
  goldflow.ru. Реальный Veo 3.1 через прямой Gemini API (НЕ Flow, несмотря
  на название конкурента — честно указано в подзаголовке). Кадры/
  Референсы/Модели/Формат — всё реальное. Убран весь фейковый fallback
  (раньше при ошибке рисовалась canvas-анимация и говорилось «успешно
  сгенерировано» — враньё, убрано полностью). Формат: Veo API реально
  поддерживает только 16:9/9:16 — остальные 3 кнопки видны, но честно
  задизейблены, не притворяются рабочими.

- **Картинки** (`ImageStudio.tsx`) — был ПОЛНОСТЬЮ фейковым экраном
  (`setTimeout` + рандомная циферка). Переписан целиком под референс:
  реальная генерация, упорядоченные референсы (номер = приоритет),
  «В монтаж» реально добавляет сцену и пересчитывает таймлайн.

- **Модели картинок**: `HARBOR_SEAL`/`NARWHAL` → `gemini-2.5-flash-image`,
  `GEM_PIX_2` → `gemini-3-pro-image-preview` (`IMAGE_MODEL_MAP` в server.ts).

## Автосохранение проекта (IndexedDB) — новое, важное
Раньше `project` жил ТОЛЬКО в React-памяти App.tsx — любая перезагрузка
страницы стирала всё, включая кастомные стили и эталон героя. Это была
причина повторяющейся жалобы «стиль не сохраняется».
- `src/utils/projectStorage.ts` — `saveProjectToDb`/`loadProjectFromDb`
  через IndexedDB (не localStorage — там лимит ~5-10MB, а тут base64
  картинки стилей/героя/сцен легко его превышают).
- App.tsx: автосохранение с debounce 400мс при любом изменении `project`.
- ⚠️ **Критичный нюанс, из-за которого фикс не работал с первого раза**:
  загрузка из IndexedDB асинхронная. `ContentFactory` читает
  `project.customStyles`/`heroRefImage`/`heroName` в СВОЙ локальный
  `useState` только один раз при монтировании — если успеть открыть
  фабрику раньше, чем подгрузится сохранённое, компонент навсегда
  захватывает пустышку. Исправлено: `App.tsx` теперь не рендерит НИ ОДИН
  экран, пока `isProjectLoaded` не станет true (короткий спиннер на
  старте) — гарантирует, что любой дочерний компонент при первом монтировании
  уже видит настоящие данные.

## Реальный рабочий рецепт Lumean API
```bash
# 1. Шаблон (кешируется в lumeanTemplateCache)
curl -X POST https://api.lumean.app/api/public/templates \
  -H "X-API-KEY: $KEY" -H "Content-Type: application/json" \
  -d '{"service_key":"elevenlabs","name":"x","config":{"tts_settings":{"mode":"mode_v1","model_id":"eleven_multilingual_v2","voice_id":"21m00Tcm4TlvDq8ikWAM","language_code":"ru","advanced_voice_settings":true,"voice_settings":{"stability":0.5,"similarity_boost":0.75,"use_speaker_boost":true,"speed":1.0}}}}'
# 2. Заказ — template_id = поле "id", НЕ "slug". Кириллица через inline -d
#    в git-bash на Windows ломает JSON — писать в файл, слать --data-binary
curl -X POST https://api.lumean.app/api/public/orders \
  -H "X-API-KEY: $KEY" -H "Content-Type: application/json" \
  --data-binary "@order.json"   # {"template_id":"<id>","input_text":"..."}
# 3. Poll GET /orders/{id} до status:"completed"
# 4. Signed URL — обязательно POST, не GET:
curl -X POST https://api.lumean.app/api/public/storage/url \
  -H "X-API-KEY: $KEY" -d '{"path":"<путь из files/service_files>"}'
```

## Общие уроки этой сессии
- Юзер очень чувствителен к фейковым/декоративным элементам UI — находил их
  регулярно (canvas-заглушки, alert()-кнопки, мёртвые Flow-енумы в UI,
  проект без персистентности). Проактивно искать и чинить попутно.
- «Не трать лимиты» — минимизировать живые тестовые вызовы Gemini/Lumean,
  полагаться на `tsc --noEmit` + чтение кода + изолированные Node-тесты
  чистой логики (без реального API) для проверки алгоритмов.
- Vite HMR после десятков правок подряд иногда даёт устаревший бандл в уже
  открытой вкладке браузера — при странном/невоспроизводимом баге сначала
  проверять в СВЕЖЕЙ вкладке или через жёсткий рефреш, прежде чем искать
  логическую ошибку в коде.
- Юзер сперва просил убрать «Персонажи и локации» (думал, что у конкурента
  нет), затем прояснил: убирать не надо, было недопонимание — важна была не
  сама секция, а то, чтобы софт автоматически держал персонажа консистентным.
- Когда юзер даёт конкретную числовую формулу (как с N=floor(сек/4)) —
  реализовывать её буквально, не подменять своей эвристикой.
