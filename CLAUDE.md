# GoldFlow Studio — статус проекта (обновлено 2026-09-24, поздний вечер)

Собрано через AI-билдер (Gemini/Google AI Studio Build) по образцу реального
сайта goldflow.ru. Реальный Node/Express-бэкенд (`server.ts`, `npm run dev`
через `tsx`).

## Ключи в `.env` — оба реальные и рабочие
Сами значения ключей лежат только в `.env` (он в `.gitignore`, в репозиторий не попадает) — сюда их не вписывать даже временно.
Проверка: `curl localhost:3000/api/health` → `hasApiKey:true, hasLumeanKey:true`.
⚠️ `gemini-2.5-pro` **отключена для новых ключей** (живой 404-тест) — текст
идёт через `gemini-3.1-pro-preview`. Google часто переименовывает
image-модели — если начнёт падать "model not found", свериться со списком в
текущем Google AI Studio.

## Что реально работает (весь конвейер 01-06, честно проверено)
Основной экран — `ContentFactory.tsx`, вкладка «Пакетная мастерская» (дефолт).
- **01-03 Архитектор/Сценарист/Раскадровщик** — `/api/generate-script`
  (Gemini, structured JSON). Языки на выбор (`ELEVEN_LANGUAGES`), длина
  роликов до 30 мин + свой вариант мин/сек. `nineFields` и
  `heroMaster.appearance/clothing/keyFeature` всегда на английском (промпты
  для картинок), `title/scriptLine/objective` — на выбранном языке.
- **Точный хронометраж** — не «выбери разумное число блоков», а жёсткий
  расчёт: `targetBlockCount = clamp(round(targetSeconds/4), 3, 25)`,
  `charsPerBlock` считается от оставшегося времени. Живой тест: 180 сек цель
  → 175.3 сек факт (25 блоков, ~97% точность). **Потолок 25 блоков за один
  вызов** — 60 блоков (5 мин) не укладывались в 120 сек и не завершались.
  Для по-настоящему длинных роликов (20-30 мин, сотни промптов) это НЕ
  решено — юзер прямо спросил «как у конкурента, без предела, за секунды» —
  ответ: конкурент физически не может делать это через LLM-вызов на кадр,
  скорее всего у них один быстрый LLM-вызов на весь текст + промпты
  собираются программно (без индивидуальной режиссуры по 9 полям на кадр).
  Юзер думает над трейдоффом (качество/кадр vs скорость+безлимит), решения
  пока нет — **не начинать без явного да**.
- **04 Эталоны героя** — после сценария автоматически генерится портрет
  героя (Nano Banana), сохраняется в `heroRefImage` state, передаётся как
  `heroReferenceImage` в КАЖДЫЙ кадр батча при «Посчитать и запустить».
  Зелёная плашка в UI показывает что подключено.
- **05 Оживление (Ken Burns)** — НЕ моя правка, но проверено вживую и
  реально работает: `realVideoExporter.ts` рендерит покадрово через
  `requestAnimationFrame`, `proceduralCanvas.ts` считает scale/translate от
  `progress=timeSec/durationSec` и `motionType` (zoom-in/out/pan-left/right).
  Теперь автоматически выигрывает от реального `durationSec` (пункт ниже).
- **06 Монтаж по словам озвучки** — **реально работает**, это была самая
  большая дыра, теперь закрыта:
  - `server.ts` → `/api/synthesize-voice` — настоящий вызов Lumean TTS API
    (создание template → order → poll → скачать `subtitles.srt` → распарсить
    таймкоды по фразам). Один вызов на весь сценарий, Lumean САМ режет на
    предложения — совпадает 1:1 с разбивкой сцен по блокам.
  - После генерации сценария duration каждой сцены **перезаписывается**
    реальным таймкодом из SRT-cue (`cue.endSec - cue.startSec`), НЕ
    оценкой по символам. `project.narrationAudioUrl` хранит ссылку на mp3.
  - ⚠️ НЕ проверено: подхватывает ли плеер/рендер Монтажа
    `narrationAudioUrl` для реального аудио-плейбека (это код до меня).
- **Стиль** — секция упрощена до «Без стиля» + «Свой стиль» (фейковые
  пресеты Кинематографичный/аниме/Миниатюра убраны — не влияли на
  генерацию). `CreateStyleModal.tsx` — реальная загрузка до 6 эталонов +
  негативный промпт, реально уходят в Nano Banana с явной инструкцией
  «копируй СТИЛЬ рендеринга, не содержание референса» (без этой фразы 2D-
  референс всё равно генерил кинематографично).
- **Персонажи и локации** — «Разобрать сценарий» реально зовёт
  `/api/parse-scene-elements`, находит повторяющихся персонажей/локации в
  тексте, заполняет счётчики настоящими числами. Кнопка «Согласовать... 17
  шт» была чистой фейковой кнопкой (хардкод 17) — удалена совсем.
- **Модели картинок**: `HARBOR_SEAL`/`NARWHAL` → `gemini-2.5-flash-image`,
  `GEM_PIX_2` → `gemini-3-pro-image-preview` (см. `IMAGE_MODEL_MAP` в
  server.ts).

## Flow-мост — код остался, но НЕ используется в генерации
`flowBridge.ts`/`flowProxyTunnel.mjs` реализованы и технически корректны
(запрос байт-в-байт совпадает с настоящим), но упёрлись в стену: recaptcha
Enterprise отличает токен от настоящего клика от токена из программного
вызова `execute()` — подтверждено A/B-тестом. Юзер отказался переходить на
клики по UI (это единственный обход). **Убрал попытку Flow из
`/api/generate-image`** — она делала `flowBridge.getFlowStatus()` первым
шагом на КАЖДОЙ картинке, а протухшее окно Chrome вешало это на 30 сек —
именно это, а не модель, было причиной жалобы «NB2 Lite генерит очень
долго». `/api/flow/status` и `/api/flow/login` эндпоинты остались (не
трогать без явной просьбы вернуться к теме Flow).

## Реальный рабочий рецепт Lumean API (набито кровью, см. ниже частые ошибки)
```bash
# 1. Шаблон (один раз на voice_id+lang, сервер кеширует в lumeanTemplateCache)
curl -X POST https://api.lumean.app/api/public/templates \
  -H "X-API-KEY: $KEY" -H "Content-Type: application/json" \
  -d '{"service_key":"elevenlabs","name":"x","config":{"tts_settings":{"mode":"mode_v1","model_id":"eleven_multilingual_v2","voice_id":"21m00Tcm4TlvDq8ikWAM","language_code":"ru","advanced_voice_settings":true,"voice_settings":{"stability":0.5,"similarity_boost":0.75,"use_speaker_boost":true,"speed":1.0}}}}'
# 2. Заказ — ВАЖНО: template_id = поле "id" из ответа выше, НЕ "slug"
#    Текст кириллицей через inline -d '...' в git-bash на Windows ЛОМАЕТ JSON
#    (даёт непонятную ошибку "template_id/task_type required") —
#    писать в файл и слать --data-binary "@file.json"
curl -X POST https://api.lumean.app/api/public/orders \
  -H "X-API-KEY: $KEY" -H "Content-Type: application/json" \
  --data-binary "@order.json"   # {"template_id":"<id>","input_text":"..."}
# 3. Poll GET /orders/{id} до status:"completed"
# 4. result.result.service_files содержит subtitles.srt/.vtt/.lrc/alignment.csv/result.json
#    result.result.files[0] — mp3. Оба требуют signed URL:
curl -X POST https://api.lumean.app/api/public/storage/url \
  -H "X-API-KEY: $KEY" -d '{"path":"<путь из files/service_files>"}'  # POST, не GET!
```
`alignment.csv` — таймкод ПО КАЖДОЙ БУКВЕ. `subtitles.srt` — по предложению
(ровно то, что нужно для сцен). Всё это реализовано в `server.ts` →
`/api/synthesize-voice`, см. `parseSrt()`/`lumeanFetch()`/
`getOrCreateLumeanTemplate()`.

## Общие уроки этой сессии (стоит помнить)
- Юзер очень чувствителен к фейковым/декоративным элементам UI (хардкод
  чисел, тосты без реального действия, статичные canvas-заглушки выдаваемые
  за готовые кадры) — находил их регулярно, каждый раз требовал реальной
  реализации, а не имитации.
- «Не трать лимиты» — минимизировать живые тестовые вызовы Gemini/Lumean,
  полагаться на `tsc --noEmit` + чтение кода, тестировать по-настоящему
  только когда это действительно нужно для диагностики.
- При зависаниях бэкенда первым делом проверять `/api/flow/status` — Flow
  bridge протухает и виснет молча, маскируясь под «медленную генерацию».
